六艺十式徒手训练小程序（原生小程序 · 零后端 · 数据只存本机）

一句话

整套流程只靠一个 Node 运行时、零运行时依赖 （测试链只有一个官方 devDependency：miniprogram-automator）—— 用 Node 内置 node:test 跑「纯函数 / 存储 / 页面 / 界面质量」四层断言（页面层靠自写的 wx/Page 打桩直接驱动真实页面代码， 界面质量靠从真实 WXSS 读色值按 WCAG 公式复算）， 再用微信官方的 miniprogram-automator 经 WebSocket 接进开发者工具里的小程序真实运行时做 E2E （evaluate 调真实事件处理函数 + mp.screenshot 截图）， 用自写的零依赖 PNG 解码器 + 行暗度指纹把 19 张截图变成视觉基线， 最后由开发者工具 CLI 负责编译/上传、Git 分支护栏 + GitHub Actions 守发布门。

2六层技术清单

每行 = 一层，三列 = 用什么 / 干什么 / 为什么值得。

层用的技术一句话作用
L1–L3 数据 / 逻辑 / 存储 node:test + node:assert，纯 CommonJS 纯函数 秒级、零依赖，覆盖绝大多数"判断类"bug
L1b 数据来源 来源快照 JSON + 逐条对齐断言 把"数据抄错一个数字"这种界面上看不出的错挡住
L4 页面 自写 wx/Page 打桩（tests/helpers/miniapp-stub.js） 让真实页面代码在 Node 里被驱动，抓"页面把数据拼错了"
L4b 界面质量 正则读 WXSS + WCAG 对比度公式 + rpx 阈值 对比度/字号/点按区变成算得出来的断言，零噪声
L6 / L6b E2E 与截图 miniprogram-automator ↔ cli auto WebSocket；零依赖 PNG 解码 + 指纹比对 在真实运行时里跑 102 条断言、19 张截图做视觉回归
L5 + 发布门 开发者工具 CLI（preview/upload）+ .githooks/pre-push + release:check + GitHub Actions 编译/上传/版本号/分支与工作区全部可复算

3最小必需三件套（换项目只留这些也能跑）

① 内置测试器 + 一层纯函数断言

node:test，零依赖、秒级。业务逻辑抽成纯函数是前提。

② 一层"打桩 + 真实代码"的页面断言

给 wx / Page 打桩，让页面代码在 Node 里被真正驱动 —— 专抓"数据拼错了"。

③ 一个「期望条数常量」守卫

EXPECTED_CHECKS：断言条数对不上就报警，防"中途崩了却报全绿"。

其余（E2E、截图基线、发布门、界面质量）都是按需再加的层 —— 它们不是"更高级"，而是各管一段不同的风险。
