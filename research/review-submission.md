## 2. 服务类目与用途说明（最容易被卡的一步）

**首选**：`体育 > 在线健身`
**被要求补充资质时**：退到 `工具 > 效率`，并把简介里的措辞往"记录"靠（见下）

提审时如果让你写「功能说明 / 用途」，用这段（我按"记录工具"而不是"健身指导"写的）：

```
本小程序是一个离线训练记录工具，不提供在线课程、不做一对一指导、不涉及付费。
用户按内置的六类徒手动作（俯卧撑/深蹲/引体向上/举腿/桥/倒立撑）各十式，
自行选择当前在练的一式，记录每次训练的组数与次数，程序按内置标准给出"是否达标、
还差几组几次"的提示，并在达标后解锁下一式。全部数据仅保存在用户手机本地，
不上传服务器、不收集任何个人信息、无需登录。
```

**为什么这么写**：审核对"线上健身指导服务"敏感（可能要求《增值电信业务经营许可证》或体育类资质）；
而"工具/记录"类目对个人主体友好。我们的产品**客观上就是记录工具**（零后端、零课程、零指导），所以这么写不是包装，是准确描述。

## 3. 《用户隐私保护指引》逐项填法

路径：后台 → 设置 → **服务内容声明** → 用户隐私保护指引。
官方说明：[用户隐私保护指引填写说明](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/)

**我们的真实情况（请按这个填）**：

| 后台问什么 | 怎么填 |
|---|---|
| 是否收集用户信息 | **不收集**（所有采集项都不勾） |
| 是否使用微信登录 / 获取用户信息 | **否**（代码里没有 `wx.login`、没有 `wx.getUserProfile`） |
| 是否获取位置 / 相册 / 麦克风 / 摄像头 / 通讯录 / 剪贴板 | **否**（代码里没有这些 API） |
| 是否有服务器 / 域名请求 | **否**（零网络请求，没有配置任何 request 合法域名） |
| 数据存储位置 | **仅用户手机本地**（`wx.setStorageSync`，键 `cf_state_v1`）；卸载小程序即清除 |
| 第三方 SDK | **无** |

> **为什么不收集也必须填**：这是平台的前置要求，不填会卡提审。
> 我们填"不收集"是**如实陈述**，不是走形式 —— 代码里确实一条用户信息 API 都没有（这点你可以让审核员随便测）。
>
> **一个诚实的补充**：我们读了 `wx.getAccountInfoSync().miniProgram.envVersion` 用来判断"当前是开发版还是正式版"，
> 以便在正式版隐藏调试入口。这是**运行环境标识**，不是用户信息、也不上传，所以不在"收集个人信息"范围内。

```
【功能说明】
离线训练记录工具，无需登录、无后端、无网络请求，数据仅存本机。
内置六类徒手动作（俯卧撑/深蹲/引体向上/举腿/桥/倒立撑），每类十式，
按"达到标准才解锁下一式"的阶梯设计。

【测试路径】
1) 首页点击顶部推荐卡片「开始这一式」→ 进入动作详情
2) 点「中级」一键填入 2 组 × 25 → 点「完成本次训练」→ 弹出达标提示（未达标会写明还差几组几次）

4) 任意进入第 3 式（未解锁）可见：只能查看动作图与三档标准，不能记录
5) 首页底部「把六艺十式发给朋友一起练」为分享入口；动作详情页点示意图可看大图

- 无登录、无支付、无广告、无用户生成内容
- 数据存本机：卸载或清缓存后进度会清空（产品设计如此，非缺陷）
- 动作标准与要点为整理/自撰内容，页面已标注免责声明；动作示意图为自绘
```

| 可能的拒绝理由 | 我们的应对 |
